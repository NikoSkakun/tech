# Content export — `docs/volumes/<volume>/chapters/_export/<chapter-id>.json`

Generated by `tools/content/export_content.py` from the chapter documents `docs/volumes/<volume>/chapters/<id>.md`.
**Never edit these files and never retype Ukrainian text from the documents** (DECISIONS §43, §49): import the JSON.
If a text is wrong, fix the chapter document, then run

```
python3 tools/content/export_content.py --volume <volume>   # regenerate the volume's files (default volume: no flag)
python3 tools/content/doccheck.py                           # must be ALL GREEN (all volumes; includes the round-trip check)
tools/content/regen.sh                                      # everything generated, all volumes, then doccheck
```

Every tool takes `--volume <id>` (default: `app/src/volumes/library.json → defaultVolume`) or `--all`.
`<volume>` in this file is the volume id (`electricity`); a volume is described by
`app/src/volumes/<volume>/volume.json` (journey order, groups, parents, the name of the axis header field,
extra documents and checks) — see `docs/VOLUMES.md`.

The structure is described by `tools/content/export.schema.json` (JSON Schema 2020-12; `schemaVersion` 2 since
the library of volumes: `volume`, `axisLabel` / `axisRaw`, full-address cross-reference targets). One file per
chapter, steps in order.

## What is on-screen copy and what is guidance

| Field | Use |
|---|---|
| `title`, `steps[].title`, `learningGoals[]` | on-screen |
| `steps[].panel[]` | on-screen panel pages, in order (≤ 450 characters of plain text each) |
| `steps[].terms[]` | on-screen term cards: `international` first, then `ukrainian`, optional `symbol` / `unit`, `definition`; `raw` is the term line as written |
| `steps[].formulas.items[]` | on-screen formulas; `formulas.raw` keeps the explanatory words around them |
| `steps[].facts.items[]` | on-screen fact chips: `text`, optional `source`; `facts.note` is a remark for the builder |
| `steps[].hotspots[]` | `international` / `ukrainian` name and on-screen `text`; `note` and `tail` are remarks for the builder (where the hotspot sits, link target) |
| `steps[].misconceptions[]` | `myth` (on-screen, the wrong belief) and `correction` (what the scene shows / says) |
| `glossary[]`, `quiz[]` | on-screen; `quiz[].correct` is a 0-based index into `options` |
| `steps[].see`, `steps[].interaction`, `steps[].transition`, `steps[].links`, `visualIdea`, `accentMood`, `notes[]`, `termsNote`, `hotspotsNote` | **guidance for the builder**, not copy. UI labels quoted inside «…» in `interaction` texts are copy and must be used verbatim |
| `models[]` | ids and titles of the simulation models; the specification and control points stay in the document section «Модель симуляції» |
| `volume`, `id` | the chapter's volume and id; the full chapter id is `<volume>/<id>` |
| `axisLabel`, `axisRaw` | the chapter's place on the volume's journey axis (header field named by `volume.json → axis.label`; «Масштаб» for electricity): short label and full text |
| `crossReferences[]` | in-app links: `targets` are full step addresses `volume/chapter/step` (see `docs/volumes/<volume>/INDEX.md`). In the documents a reference inside the volume is written `chapter/step`, one into another volume `volume/chapter/step`; the export always has the full form |

## Text conventions

- Mini-markup inside strings: `**term**` (key term, bold), `_emphasis_`, `` `formula` `` (render as formula / mono).
  A code span of the form `` `chapter/step` `` inside copy is a link to that step, not a formula.
- U+00A0 (non-breaking space) between a number and its unit and in thousands groups is significant — keep it.
  The apostrophe is ’ (U+2019).
- Quotes are already levelled for the screen: the «…» that delimit a page or hotspot text in the documents are
  stripped, first-level quotes are «…», nested ones „…“. Do not re-process them.
- Palette tokens appear in backticks in guidance fields (`` `cyan` ``, `` `plantType.wind` ``) — STYLE_GUIDE §2.2.
- `interaction.items[].controls[]` is a best-effort parse (type, label, min / max / step, unit, default as written);
  the item `text` is authoritative. Numbers use a decimal point in `min` / `max` / `step`; `default` is the raw text.

## Guarantees checked by `doccheck.py`

Every panel page, term, formula field, fact, interaction item, hotspot, misconception, transition, quiz item,
glossary row, learning goal and cross-reference of a document is present in its export (round-trip comparison of
the letters and digits, field by field), every file validates against `schema.json`, every quiz item has at least
two options and exactly one correct index, and the files on disk are identical to a fresh run.
After export_content.py always run tools/content/export_runtime.py (generates app/src/volumes/<volume>/content/generated/<id>.json for the app); doccheck.py verifies both.

## Runtime files — `app/src/volumes/<volume>/content/generated/` (what the app imports)

`tools/content/export_runtime.py` turns each export into two files for the app (types: `app/src/content/types.ts`):

| File / field | Use |
|---|---|
| `<id>.json` | the on-screen subset of the export, loaded lazily with the scene: `defineContent(raw, { labels })` |
| `steps[].terms[].name`, `.intl` | DECISIONS §54: `name` = display name (Ukrainian form, «… (BMS)» where an abbreviation is kept), `intl` = international form as a secondary line (omitted when already in `name`). Show `termName(t)`, never `international` first |
| `glossary[].name`, `.intl` | same rule; the glossary is sorted / indexed by the Ukrainian alphabet, search matches both |
| `steps[].hotspots[].id` | stable slug of the international name (`wind-turbine`) — bind with `hotspots: [{ content: id }]` (or an index) instead of matching titles |
| `steps[].hotspots[].title`, `.intl` | display name of the hotspot card (§54) and its international secondary line; `name` keeps the pair as written (`Nucleus — ядро`) |
| `steps[].labels[]` | UI labels quoted «…» in the step's «Інтерактив» items, verbatim, in order — use them for control captions instead of retyping |
| `steps[].facts.items[].table` | `{ head, rows, note? }` when the fact is a table in the document; the HUD renders a table (row cards above 4 columns) — never parse the pipes of `text` |
| `crossReferences[]` | rendered by the HUD as «Див. також» chips in the step their `where` names |
| `labels` (chapter level, optional) | free-form scene labels the builder adds in `defineContent(raw, { labels })` — §54 applies |
| `<id>.manifest.json` | eager, small: `id`, `title`, `subtitle` (= first step title by default), `axisLabel`, `group`, `parent`, `order`, `steps[] { id, title, blurb }` (blurb = first sentence of the step’s first panel page, ≤ 140 characters). Import it in `index.ts`: `defineChapter({ …, ...manifestText(meta) })` — never import `<id>.json` there |

`app/src/content/__tests__/generated-meta.test.ts` checks the manifests against the exports; `doccheck.py` checks
that the generated files equal a fresh run.
